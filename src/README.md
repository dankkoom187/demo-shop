# ПЛЁНКА ПРО — прототип интернет-магазина защитных плёнок

Многостраничный прототип магазина: каталог, карточка товара, сравнение, гид по выбору, корзина и
оформление, юридические страницы. Сделан как статический сайт — открывается локально и после сборки
без бэкенда, логика интерфейса полностью рабочая.

> Товары, цены и сроки службы — демонстрационные. Оплата, CRM и почтовые уведомления не подключены:
> проект показывает логику интерфейса, а не боевой магазин.

## Структура

```
src/
  partials/     общие части: head, шапка, подвал, корзина-drawer, тосты
  pages/        контент каждой страницы (home.html → index.html)
  data.js       каталог, статьи, справочники
  pages.js      логика страниц: товар, сравнение, гид, статья, корзина, формы
app.js          общая логика: каталог, корзина, сравнение, drawer, валидация
styles.css      дизайн-токены, компоненты, адаптив
tools/          сборка, сервер, тесты, аудит, скриншоты, публикация
docs/           вопросы заказчику и решения по пунктам ТЗ
dist/           собранный сайт (генерируется)
dist-onefile/   весь сайт одним файлом (генерируется)
```

## Команды

```bash
npm install
npm run dev        # http://localhost:5173 — отдаёт dist/
npm run build      # собрать страницы из partials + pages в dist/
npm run lint       # ESLint 9
npm run format     # Prettier
npm run test       # проверка страниц + сценарные тесты в headless Chrome
npm run audit      # доступность (axe-core), дубли ID, битые ссылки, вес страниц
npm run check      # lint + format + build + test + audit
npm run publish    # однофайловая сборка + скриншоты для портфолио
npm run pages      # подготовить репозиторий для GitHub Pages
```

Chrome ищется автоматически (Program Files → AppData → macOS/Linux), путь можно задать
переменной `CHROME_PATH`.

## Что проверяется автоматически

**`npm test` — 14 страниц + 24 сценария:**

- нет горизонтального переполнения на 375 и 1440 px, нет ошибок JS в консоли;
- нет битых внутренних ссылок, на месте ключевые элементы каждой страницы;
- каталог: фильтр по толщине, поиск по коду, сортировка по цене, переход из категории на главной;
- карточка: цена меняется вместе с вариантом ширины (1,58 / 1,80 м), количество, похожие товары;
- корзина: вариант сохранён, скидка 10% пересчитывает итог, состояние живёт между страницами;
- оформление: юрлицо показывает ИНН и счёт, самовывоз скрывает адрес, валидация не пропускает пустое;
- сравнение: не смешивает группы, таблица на 8 строк, удаление позиции;
- гид: 5 статей, фильтр по теме; статья открывается по `?slug=`;
- формы: валидация и отправка.

**`npm run audit`:**

- дубли `id`, поля без `label`, кнопки без доступного имени, `img` без `alt`, число `h1`;
- доступность по axe-core — сейчас **0 нарушений** на всех 14 страницах;
- вес страниц: 5 запросов, 8–19 КБ;
- работоспособность кнопки закрытия корзины и однофайловой сборки.

## Перенос в Tilda

1. `styles.css` → _Настройки сайта → Код в HEAD_ (без `:root`, токены — в настройки дизайна).
2. Шапка и подвал — Zero Block, ссылки как в `partials/`.
3. Каждая страница — Zero Block по блокам из `src/pages/*.html`, каталог — «Каталог товаров»
   либо T123 с разметкой `.catalog`.
4. Фильтры и поиск — штатные + код; сравнение, скидка и расчёт — только кодом (см. `app.js`).
5. Формы — блок «Форма» с передачей в amoCRM, SmartCaptcha.
6. Аналитика — Метрика: `form_submit`, `add_to_cart`, `begin_checkout`, `purchase`, `contact_click`.

## Честно: что Tilda закрывает, а что нет

| Требование ТЗ                         | Tilda | Почему                                           |
| ------------------------------------- | ----- | ------------------------------------------------ |
| Вёрстка, адаптив, анимации            | ✅    | Zero Block + код в HEAD                          |
| Каталог, категории, импорт товаров    | ✅    | Каталог товаров, импорт CSV                      |
| Фильтры, поиск по коду, сортировка    | ✅/⚠️ | Фильтры штатные, поиск и сортировка — кодом      |
| Варианты ширины с разной ценой        | ❌    | Нет вариантов с разной ценой — код или WordPress |
| Сравнение по 8 параметрам, по группам | ❌    | Только самописный код                            |
| Скидка 10% на первый заказ            | ❌    | Нет истории гостевых заказов                     |
| Оплата и статус «Оплачен» по вебхуку  | ✅/⚠️ | Платёжные системы есть, свои вебхуки ограничены  |
| amoCRM: заказы + 5 форм               | ✅/⚠️ | Формы штатно, состав заказа — доработкой         |
| Роли, статусы, бэкапы                 | ❌    | Админка Tilda своя                               |

**Вывод:** Tilda закрывает вёрстку, витрину, формы и часть оплаты, но логика из ТЗ (варианты с
разной ценой, сравнение, скидка первого заказа, статусы и роли) уходит в самописный код. Для
боевого проекта из ТЗ WordPress + WooCommerce рациональнее; прототип на Tilda — портфолио и быстрый
способ согласовать интерфейс с заказчиком.
